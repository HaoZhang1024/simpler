# SWA percounter 时延对照：t22、t25、t35

先用黄区已有的 **A6 L4 正式轮次**与蓝区已归档的 A5 L4 对齐。黄区已完成干净目录功能验收，本轮只处理已有记录。历史 L0 均值为 A5 185.173 µs、A6 265.768 µs，差 80.595 µs；两者来自不同 runtime 工作树。下面的 L4 数据用于判断差异出现在哪一步，L0 保留为生产耗时口径。[A5 trace](../results/2026-11-19-a5-percounter-l4/README.md) · [A6 实测摘要 §7](a6-result.md)

## A5 已对齐的时间点

单位 µs，时间原点为本轮所有 kernel 中最早的开始时间。表中前驱取依赖边指向本任务、且在 Worker View 有 kernel 区间的直接前驱里最后结束者。dispatch 取本任务所有区间中最早的本地 dispatch；首次 dispatch 与首个 kernel 可以来自不同 worker。

| 源任务 / 回放 ID | 区间 / 核数 | 最晚计算前驱 | 前驱结束 → 首 dispatch | 首 dispatch → 首 kernel | 首 kernel → 末 kernel 结束 | 启动分散时间¹ |
| --------------- | ----------- | ------------ | ---------------------- | ----------------------- | ------------------------- | ------------- |
| t22 / 14 | 72 / 72 | t18 | 27.813 | 1.193 | 168.486 → 190.409，跨度 21.923 | 10.625 |
| t25 / 17 | 64 / 64 | t22 | 4.324 | 1.325 | 196.058 → 215.161，跨度 19.103 | 12.703 |
| t35 / 27 | 64 / 64 | t29 | 3.276 | 1.292 | 308.153 → 320.997，跨度 12.844 | 6.721 |

¹ 最晚 kernel 开始减最早 kernel 开始。前驱结束至 dispatch 是两个可观测端点之间的差值。t22 另有无 kernel 的前驱 t21，t25 有 t23、t24；即使是可见的计算前驱，其 kernel 结束到完成计数发布也可能有间隔。因此这列只能定位待拆解的窗口，不能直接记为 ready 等待或 GM 轮询开销。[A5 完整字段与计算结果](../results/2026-11-19-a5-percounter-l4/task-comparison.json)

| 对比点 | A5 L4 实测 | 黄区优先回答的问题 |
| ------ | ---------- | ------------------ |
| t22，同步 MIX | 24 个 1C2V block；func 18（C）24 段，中位/最大 12.803/19.053；func 19（V）48 段，12.696/17.092。每个活跃核只执行该任务一次 | A6 为 48 个 1C1V block，预期 C/V 各 48 段。原报告按 A5 48 个 block 推算的双波收益应撤回。对照 A6 的前驱结束→dispatch、组内会合、C/V 启动分散、各函数时长，确定延迟增加在启动前还是执行中 |
| t25，普通 Vector | func 20 的 64 段由 64 个核各跑一次；中位/最大 6.511/7.760 | A6 有 54 个 Vector，64 个 block 必有核被复用。统计实际用了多少核、各跑几段、同核相邻段间隔，查最后结束的是第几次执行 |
| t35，普通 Vector | func 27 的 64 段由 64 个核各跑一次；中位/最大 7.330/9.185。最后一个区间也是本轮整图最后一个 kernel | 除同核复用外，核对 A6 决定 t35 开始的最晚计算前驱，以及末段是否仍决定整图结束 |

现有 A6 **L3** 报告的三个跨度分别为 34.6、42.5、32.8 µs，只用于选取要查的区间。两次 L4 的任务跨度差、前驱间隙差均需以同字段重算。三个任务可能与其他工作重叠；先查关键路径，再讨论端到端影响。整图 L0/L4 比值不能用来把某个任务的 L4 差额折成生产耗时。

## 黄区提取与反馈

若 t22 的最后到达与首 dispatch 之间存在明显间隔，按[GM 与 CntNotify 并发测试](a6-register-benchmark.zh-CN.md)对照 A6 同址访问、48 个 block 的到达计数和实际放行时间。

1. 选择已有 A6 L4 的同一正式 invocation，确认原始 records 中 chip_swimlane_level=4，输出校验通过。记录 run 编号、runtime 版本或现场补丁身份、计数器频率、总区间数（预期 570）、truncated/dropped 状态。使用这个 run 的 `deps.json`、`source-task-map.txt` 和已转换的 Perfetto JSON；仅有原始 records 时，先用现场版本的 swimlane_converter 带上同轮依赖转换。保留 A5 单轮无预热与 A6 有预热的差别。
2. 从 Simpler 根目录执行以下命令。`TRACE` 是 Worker View 完整 trace（JSON 或 JSON.gz），`MAP` 是同轮的编号表（第一列原任务，第二列回放任务）。脚本只用 Python 标准库，按原任务编号聚合。返回生成的 JSON，保留三位小数，填下表。

```bash
python tests/fdwic/a6_dsv41_scheduler/compare_l4.py \
  "${TRACE:?A6 L4 Perfetto JSON}" "${MAP:?source-task-map.txt}" > a6-l4-task-comparison.json
```

| 源任务 | A6 区间/活跃核；每核执行次数分布 | 最晚计算前驱；前驱结束→首 dispatch | 首 dispatch→首 kernel；启动分散时间 | kernel 跨度；与 A5 的跨度差 | 各 func 的 n/中位/最大；同核复用间隔 |
| ------ | -------------------------------- | ----------------------------------- | ----------------------------------- | --------------------------- | ------------------------------------ |
| t22 | 待填 | 待填 | 待填 | 待填 | C/V 分列 |
| t25 | 待填 | 待填 | 待填 | 待填 | 待填 |
| t35 | 待填 | 待填 | 待填 | 待填 | 待填 |

3. **给三行数字补最小证据。** t22 返回最晚前驱的完成发布、依赖满足、分配/会合与首次 dispatch 的调度事件名、worker 和时间戳；同时给出最早与最晚启动的 C/V 参与者。若全任务 ready 或跨核发布点未被记录，填“未观测”，保留上述端点界定的总间隙。t25/t35 各返回最后结束那个核的连续记录：block、worker、func、dispatch、kernel start/end、同一任务在该核上的执行序号。该核只跑一次时，再给一个确实复用的核作对照；注明是否有其他任务穿插。
4. **回填结论。** 每个任务各写一行“差值主要出现在什么区间、依据哪条事件、是否推迟后继或整图结束”。附 L4 汇总 JSON、同轮编号表，以及可分享的事件节选或压缩 trace。两端时钟各自在本轮归零，使用相对跨度比较。资料不齐时先交已观察项。
